=== SCRIPT 1: probe_declaration.py ===
THE EXPERIMENT: does honestly declaring yourself as an AI agent change what you get?
For each target URL, fetch it TWICE, back to back, changing ONLY the User-Agent:
  - "declared" pass: the honest UA already used by this project,
    "AgentGatesBot/0.1 (+https://agentgates.surge.sh; autonomous-agent reachability
    measurement; GET-only, non-destructive)"
  - "generic" pass: a plain desktop browser UA string (use a current Chrome on macOS UA)
Everything else identical: same headers otherwise, no cookies, no JS, 20s timeout,
do not follow a redirect more than 10 hops, and record the FINAL url.

For each pass record: http status, final_url, redirect chain length, body length,
sha256 of the body, a normalized body hash (collapse all whitespace runs to a single
space and strip, so pure formatting noise does not count as a difference),
whether a bot-challenge marker is present (reuse/extend the CHALLENGE_MARKERS
concept from probe_signup.py), and the value of any WAF-ish response headers
(server, cf-ray, cf-mitigated, x-datadome, akamai-*, x-amzn-waf*).

Then classify the pair into exactly one of:
  "identical"           -> same status and same normalized body hash
  "declared_blocked"    -> generic got a usable 2xx page, declared got 403/429/503
                           or a bot-challenge page
  "declared_throttled"  -> generic 2xx, declared got 429 specifically
  "declared_downgraded" -> both 2xx but the declared pass got materially less content
                           (normalized body hash differs AND declared body is < 50%
                           the size of the generic body)
  "both_blocked"        -> neither pass got a usable 2xx page
  "declared_allowed"    -> declared 2xx/usable while generic was not (the reverse case)
  "inconclusive"        -> anything else (e.g. network error, both differ in size but
                           not enough to call it)
Run the two passes SEQUENTIALLY per target (declared first, then generic), with a
1.5-2.5s randomized sleep between the two passes and between targets, and a
ThreadPoolExecutor of 3 targets at a time. Do not hammer anyone.
